# 石名坂の記事の「型」

公開済みの記事 146本（2025-04-25 〜 2026-09-10）と固定ページ 8枚を
すべて読み込んで数えた結果です。感想ではなく、実測値です。

数え直すとき：

```
python3 wordpress/posts/check_house_style.py --corpus   # 測り直す
python3 wordpress/posts/check_house_style.py <file.html> # 下書きを点検する
```

## 1. 必ずある型（守るもの）

| 決まりごと | 守られている率 |
| --- | --- |
| 末尾の目印 `<!-- ISNZ-REL -->` → `<!-- ISNZ-CTA -->` の順 | 100% / 97% |
| 電話番号 `019-638-7521`（平日8:00〜17:00） | 100% |
| お問い合わせフォームへのリンク | 99% |
| 「前の記事へ」「次の記事へ」の画像ナビ（`wp:columns`） | 99% |
| アイキャッチ画像あり | 96% |
| 「あわせて読みたい」 | 77% |

**「前の記事へ／次の記事へ」が99%** — ここを落とすと、目に見えて他の記事と違います。
`wp:columns {"isStackedOnMobile":false}` の中に 100px のリンク画像を2つ並べ、
間に空のカラムを挟む形です。

## 2. CTAの見出しは、話題ごとに変える

`isnz-cta-heading` の中身は **8種類** を使い分けています。
「株式会社石名坂について」は全体の 14% にすぎません。

**ただし例外があります。** 技術・コラム系の記事——Claude Code 連載5本、AX の解説、AI の考察——は、そろって「株式会社石名坂について」を使っています。工事や運搬の話は話題に合わせ、それ以外は会社そのものの紹介に寄せる、という使い分けです。

| 見出し | 件数 |
| --- | --- |
| 地域の守り手として | 35 |
| 運搬・工事のご相談 | 26 |
| 工事のご相談・ご依頼 | 22 |
| 株式会社石名坂について | 20 |
| 現場の仕事を、もっと知る | 15 |
| 砕石・砂利のご注文・ご相談 | 13 |
| 除雪・排雪のご相談 | 6 |
| 建設・運搬のご相談 | 6 |

続く形は決まっています ——
見出し → 会社の一文 → `👉` 付きのリンク3本 → 電話とフォームの一行 →
40px のスペーサー → 前後の記事ナビ。

## 3. 長さ

| | 中央値 | 平均 |
| --- | --- | --- |
| 本文の字数 | 1,677字 | 2,088字 |
| 一文の長さ | 53字 | 67字 |
| 題名 | 33字 | — |

分布は 0–1k:35本、1–2k:56本、2–3k:32本、3–5k:13本、5–8k:8本、8k超:2本。
**3,000字を超えると上位16%** です。長い記事を出すなら、連載に割るのが石名坂の型
（「第N回」を題名に入れている記事が 10%、末尾の「このシリーズの記事」が 26%）。

一文が60字を超えるものは全体の 40%。長い文を書くこと自体は珍しくありませんが、
中央値は 53字です。

## 4. 題名のつけ方

| 使っている記号・語 | 率 |
| --- | --- |
| 【　】 | 46% |
| ？ | 38% |
| 「〜とは」 | 22% |
| ｜（縦棒で後ろに補足） | 20% |
| 「解説」 | 19% |
| 「第N回」「最終回」 | 10% |
| 語の前後に半角スペース（強調） | 23% |

例：「トラックの許可更新制とは？いつから始まる｜第1回」
　　「グループで分ける建設業の運送許可と更新制｜最終回」

**問いかけの形（？）が4割**。答えを題名に書ききらず、問いで止めるのが癖です。

## 5. 中身の組み立て

| | 1本あたり |
| --- | --- |
| h2 | 3.3個 |
| h3 | 4.8個 |
| 箇条書き | 2.4個 |
| 画像 | **4.3枚** |
| 表 | 0.2個 |

- 見出しは **h3 が主役**（`{"level":3,"fontSize":"medium"}` が最多）。
  h2 は CTA の見出しなど、節の切れ目にだけ使う。
- 本文の段落に `fontSize:medium` を付けているのが 63%。
- 1枚目の画像は **本文の5ブロック目あたり**（3ブロック以内が45%）。
  書き出しの段落が終わったらすぐ絵、という流れ。
- 「まとめ」が 52%、「ポイント」が 30%。

## 6. 書きぶり

**書き出しは三段。** 話題 → この記事で何を書くか → **それが石名坂自身とどう関わるか**。
三つ目が石名坂らしさの核で、「他人事として書ける立場ではありません」のように、
自分を当事者の側に置きます。

地名を出す率が高い：**盛岡 84%**、岩手 46%、現場 46%。
全国の話でも、最後は盛岡の話に落とします。

### ただし、記事の種類で分かれます

連載を種類別に見ると、はっきり割れていました。

| 連載 | 種類 | 地名・自社 |
| --- | --- | --- |
| トラックの許可更新制（全4回＋最終回） | 制度・業務 | **全回にあり** |
| Claude Code 入門（全5回） | 技術の解説 | **全回になし** |

**技術やしくみの解説そのものには、地名も自社も入れません。**
「なぜ速いのか」を説明している途中に盛岡を差し込むのは不自然だからです。
制度や業務の話——自分の会社が当事者である話——では、全回に入れます。

これは藤原様の指示（2026年9月）でもあります。
**「今回みたいなケースは、盛岡も自社の話を無理に入れなくても良い」。**
点検で「盛岡がない」と出ても、解説の記事なら直す必要はありません。

よく出る言い回し：

| | 率 |
| --- | --- |
| 〜ではありません（否定で誤解を先に潰す） | 24% |
| 実際に | 20% |
| ご紹介します | 18% |
| と思います（断定しすぎない） | 17% |
| つまり | 15% |
| ご相談ください | 14% |
| かもしれません | 13% |
| 結論から | 11% |

「いかがでしょうか」は 1%、「たとえば」は 3%。**使いません。**

## 7. そのほか

- スラッグは 100% 半角英数。語数の中央値は 2語（`kiban-seibi-koji` など）。
  ただし `post-170` のような自動生成のままの記事も残っています。新規は意味のある語で。
- 投稿の間隔は中央値1日、月に 5〜43本と波があります。曜日は木・月・金が多め。
- 抜粋（excerpt）を書いているのは 32% だけ。
- 「参考・出典」を置いているのは 25%。「本稿は執筆時点」の断り書きは 4%。

## 量子コンピュータの下書きは、ここが型から外れている

| | 型 | 下書き |
| --- | --- | --- |
| 前後の記事ナビ | 99%にある | **なかった → 足しました** |
| お知らせ一覧へ戻るボタン | 89%にある | **なかった → 足しました** |
| CTAの見出し | 技術記事は「株式会社石名坂について」 | 合っている |
| 本文の字数 | 中央値 1,677字 | 前編 7,108字 / 後編 8,019字（**上位数%**） |
| 1枚目の図の位置 | 5ブロック目あたり | 前編 5／後編 23 → **図を足して 13** |
| 盛岡・岩手 | 84% / 46% | 盛岡は入っている |
| 書き出しの三段目（自社との関わり） | 定型 | 弱い |

後編は書き出しから23ブロック、絵も図もないまま文字が続いていました。
六つの方式を並べた図（`fig_six_ways`）を足して、13ブロック目に前倒ししています。

前後の記事ナビと一覧へ戻るボタンは `add_nav.py` で足しました。
つなぎ先は 前編 ← 2026-09-10 の記事 → 後編 ← （次はまだないので空カラム）。
骨組みは Claude Code 連載のものと一字一句そろえてあります。

残るのは二つ。

1. **字数** — 二部構成にしてある以上、このままでよいと考えます。
   ただし公開済みの型からははっきり外れるので、承知のうえで出すことになります。
2. **書き出しの三段目** — 「それが石名坂自身とどう関わるか」。
   盛岡には出てきますが、他の記事のような当事者としての一言が弱い。
   ここは藤原様のお考えを入れたほうがよい箇所だと思います。

## 8. 出典の確かめ方（2026年9月に決めたこと）

量子コンピュータ連載（全6回）の出典44本を1本ずつ当たったところ、
**49か所直すことになりました**。記事を書いたときには気づけなかったものばかりです。
同じことを繰り返さないために、やり方を残します。

### なぜ要るか — 実際に出てきたもの

| 記事に書いてあったこと | 出典に書いてあったこと |
|---|---|
| Natureの**表紙**を飾った | どの出典にも書かれていなかった |
| メモリは1ペタバイト超 → 4ペタバイト | 約2ペタバイト → 約4ペタバイト（**倍率が2倍→4倍にずれていた**） |
| 日本の組織は六つのうち**四つ**に名前がある | 五つ（中性原子が抜けていた） |
| フアン氏は「15年から30年先」と述べた | 「15年は早すぎ、30年は遅すぎ、20年なら納得」 |
| ハーバー・ボッシュ法は400〜500度・数百気圧 | 400〜600度・100〜200気圧 |
| 実機で因数分解できた最大の数は**15と21** | 「35以下」としか書かれていない |
| 商用機は**今世紀末**までに（自動翻訳） | by the end of this **decade**（2020年代の終わり） |

### 手順

1. **記事の一文と、出典を1対1で対応させる。** まとめて「参考文献」にしない。
   どの一文がどの出典の裏づけかを、書いた本人が言えるようにしておく。
2. **出典を開いて、その一文を探す。** 見つからなければ、
   「出典が無い」として**書き方を弱めるか、落とす**。推測で補わない。
3. **数字は必ず原文の数字を写す。** 丸めるときは、丸めたと分かる書き方にする。
4. **確認できたことと、できなかったことを分けて記録する。**

### 落とし穴（今回ぶつかったもの）

- **自動翻訳を経由しない。** `decade`（年代）を `century`（世紀）と訳した例が実際にあった。
  英語の出典は、必ず原文の一文を見る。
- **見出しと本文は違う。** CNBCの見出しは「15 to 30 years away」だが、
  本人の発言は「15年は早すぎ、30年は遅すぎ、20年なら納得」だった。見出しを引き写さない。
- **リンク先が原典とは限らない。** ファインマンの論文としてリンクしていたPDFは、
  中身は大学の**講義スライド**だった。1ページ目を必ず見る。
- **記事名が違っていることがある。** Googleのブログの見出しは、記事に書いていたものと別だった。
- **日付は文書の表紙で確かめる。** 「2025年11月20日」と書いていたが、
  文書には「令和７年11月」までしか書かれていなかった。
- **要約ページと本文は違う。** 金融庁・日銀の告知ページには要点しか無い。
  本文（仮訳PDF）に当たらないと裏づけにならない記述がある。
- **数字の古さを書く。** 2019年の予測を年号なしで書くと、いまの見解に見えてしまう。
  反対論も同じで、「2018年の記事」「著者自身がごく少数派と書いている」まで添える。

### 道具

`wordpress/posts/quantum/series/naoshi_*.py` が、このとき使った直しのスクリプトです。
共通の約束はこうしてあります。

- 鍵は環境変数からしか読まない。標準出力にも出さない

- 書き込んだあと読み返し、さらに**公開ページを取得して**確かめる
