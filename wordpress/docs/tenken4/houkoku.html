まず、この3つ

01

PHPの重大な欠陥：サーバー会社の対応が「プランによって違う」ことが分かりました

カゴヤの案内（10月31日 9:10時点）では、「レンタルサーバープラン」は修正版への更新が完了しています。一方、「共用サーバー」「マネージド専用」「WordPress専用」は応急の緩和策（10月30日）だけで、PHP本体の更新は終わっていません。カゴヤ自身が「根本的な対策は、レンタルサーバープランへの変更か、対策済みPHPへの移行」と書いています。

石名坂がどちらのプランかは、外からは判別できません。カゴヤのコントロールパネルで「契約情報」のプラン名と、「Webサイト → PHP → PHPバージョン変更」のPHPの版を見てください。共用サーバーなら、プラン変更（同等以上のスペック）を制作会社と相談する段階です。レンタルサーバープランなら、PHPの版が 8.5.12／8.4.27／8.3.36／8.2.35 のいずれかになっているかを見れば終わりです。

02

前回の「最優先」は直っていました

お問い合わせフォームの裏口で、PHPの故障の中身とサーバー内の場所が丸見えになっていた件は、いまは「許可されていません」という正しい短い返事になっています。遠隔操作の古い入口（XML-RPC）は閉じたまま、WordPress本体は最新の 7.1.4、プラグイン8本もすべて最新でした。

03

速さは少し下がりました：54点（前回58点）

原因は、ページの頭でチャットボット用の部品（React など5本）が、描画を止める形で読み込まれていることです。173ページすべてで同じです。前回は後回しの読み込みだったので、チャットの部品（AI Engine）の更新で変わった可能性があります。描画の前にやる処理の時間（TBT）は150ミリ秒から430ミリ秒に増えました。

直し方：制作会社に「AI Engine のスクリプトを defer（後回し）で読む設定に戻してほしい。Autoptimize の JS 遅延でも可」と頼む。見た目は変わりません。
