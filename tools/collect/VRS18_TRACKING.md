# VRS18 予測の週次追跡

外部のAI予測（VRS18）と市場（複勝オッズ）のどちらが当たるかを、
発走前に記録して積み上げる仕組み。

## なぜ必要か

これまで7つの因子（得意コース・同距離実績・前走着順・休み明け・斤量・
脚質・外厩）を検証して、どれも市場を超えなかった。外部のAI予測も
同じ土俵で測る必要があるが、過去の的中実績が公開されていないため
事後検証ができない。そこで**発走前に記録して前向きに積む**。

運用ルールは「複勝オッズ最安を軸」＝市場そのものなので、
これは実質「市場 vs VRS18」の比較になる。

## 流れ

| 手順 | 実行者 | 内容 |
|---|---|---|
| 1 | `vrs18_prepare.py` | その日のAI予測記事を発見、予測表画像を取得、市場オッズを取得、manifest を出力 |
| 2 | モデル | `work/<date>/img/*.png` を読み、`work/<date>/predictions.json` に数値を書く |
| 3 | `vrs18_build.py` | manifest と predictions を突き合わせ、発走前の追跡ファイルを作る |
| 4 | `vrs18_score.py` | 結果が反映され次第、着順・軸の的中・対数損失を埋める（冪等、毎日実行）。`data/results/*-pass.json` の仮想ポートフォリオも同時に採点する |

```
python3 tools/collect/vrs18_prepare.py              # 当日
# モデルが work/<date>/img/ を読んで predictions.json を書く
python3 tools/collect/vrs18_build.py <date>
python3 tools/collect/vrs18_score.py                # 毎日
```

## 画像を読むのがモデルである理由

予測値は記事内のグラフ画像にしか無い（note本文は定型文のみ、
運営ポータルにも公開データソースは無い）。

tesseract によるOCRを**正解が分かっている24レース321頭（606セル）で検証**したところ、
**一致率37%**だった。`11.83→1188`（小数点脱落）、`5.87→9.87`、`15.95→19.95`
のような誤りが多く、いずれも値としては自然に見えるため後段で検出できない。
検証プロジェクトで入力データが静かに壊れるのは最悪の失敗なので採用しなかった。

## 結果反映のラグ

- 当日の `race.netkeiba.com/race/result.html` は**1着のみ公開**、2着以降は有料
- 無料DB `db.netkeiba.com` は確認した範囲で**約1週間のラグ**
  （2026-10-12時点で10/04までは反映、10/10以降は未反映）

このため `vrs18_score.py` は冪等に作ってあり、毎日実行して
反映済みのものから順に埋める。未反映は `pending` として報告される。

## 見送り記録の仮想ポートフォリオ

買わなかった日は `data/results/<date>-pass.json` に判断と根拠を残す。
`counterfactual.horses` に「買っていたらどうなったか」の対象馬を入れておくと、
`vrs18_score.py` が結果反映後に自動で採点する（的中数・回収額・回収率）。
複勝払戻は着順と同じ db.netkeiba のページから取得する。

**実際には買っていないので実損益ではない。** 見送り判断が正しかったかを
後から数字で検証するためのもの。1日分の十数点では運の幅が大きく判定にならない。

## 指標

- **主指標**: 軸（最上位推定の馬）が複勝圏に入ったか
  - 8頭以上は3着まで、5-7頭立ては2着まで（JRAの複勝規定）
- **副指標**: 全出走馬の複勝予測に対する対数損失

**軸が一致したレースは主指標に差が出ない。** 2026-10-12は24レース中19レースで
軸が一致したので、軸比較の実効サンプルは5レースだけだった。
`summary.json` の `axisSplitOnly` がこの実効サンプルにあたる。
対数損失は全レースで差が出るので全件使える。

## 注意

- 市場推定は `0.8 / 複勝オッズ中点`。レース内でΣ=3に正規化しない
  （断然人気がいる組で100%を超えるため。実際に東京3Rで105.8%になった）
- VRS18の出力は確率分布として正規化されていない
  （勝率合計 110.3〜185.0%、複勝率合計 271.5〜423.3%）。
  生値と正規化値の両方を保存する。軸の選択は単調変換なので正規化に依存しない
- 私的利用の範囲。netkeiba ToS 第16条12号（サーバ負荷）に配慮して間隔を空ける
