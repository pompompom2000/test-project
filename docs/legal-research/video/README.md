# 解説動画「傭車の考え方 ― ダンプの配車で迷わないために」

配車担当・現場向けの社内研修動画です。PDF『傭車の考え方と利用運送の登録判断』
（全83ページ・57章）から、**現場でその場で判断するために要る部分だけ**を抜いて構成しました。

## 成果物

| ファイル | 内容 |
|---|---|
| `傭車の考え方_解説動画.mp4` | 完成版。1920×1080／25fps／合成音声ナレーション入り |
| `傭車の考え方_解説動画（無音）.mp4` | 同じ映像の無音版。ご自身の声を当てる場合はこちら |
| `傭車の考え方_解説動画.srt` | 字幕ファイル。動画と同じフォルダに置けば多くのプレーヤーで自動で出ます |
| `ナレーション台本.md` | 1枚ごとの読み上げ原稿。録り直すときはこれを読んでください |

## 構成

| パート | 内容 |
|---|---|
| 0 | オープニング／この動画で分かること |
| 1 | 「傭車」という言葉がいちばん危ない |
| 2 | 3つの軸で分解する（運送責任／指揮命令／車両の使用権原） |
| 3 | 相手が誰かで手続が変わる（緑・水屋・白の3種類） |
| 4 | 緑か白かを、何で見分けるか（社名でもゼッケンでも分からない） |
| 5 | ケーススタディ ― ダンプが3台足りない日 |
| 6 | 白ナンバーを使いたくなったら（引取販売の適法・違法） |
| 7 | 積む物が産業廃棄物だったら（二階建ての規制） |
| 8 | 積み込み前の30秒チェック |
| 9 | 今日から変えること |

## 音声について

ナレーションは **open-jtalk**（オフラインの日本語音声合成）で作っています。
外部のサービスには一切送っていないので、社外に内容が出ることはありません。
機械的な声なので、正式版はご自身の声で録り直すことをお勧めします。
その場合は無音版と台本を使ってください。

音声合成が読み間違える語は、ナレーション原稿の側だけ表記を変えて回避しています
（`build.py` の `YOMI`）。

| 表記 | そのままだと | 音声用の表記 |
|---|---|---|
| 傭車 | ヤトイシャ | ようしゃ |
| 自重計 | ジチョーケー | じじゅう計 |
| 車検証 | クルマケンショー | しゃけん証 |
| 引取販売 | ヒキトハンバイ | 引取り販売 |
| 積込み | セキコミ | 積み込み |

## 作り直し方

```sh
python3 make.py
```

スライドHTML → Chromiumで1920×1080のPNG → open-jtalkでWAV → ffmpegで結合、という流れです。
所要時間は10分ほど。必要なもの：

```sh
apt-get install -y ffmpeg open-jtalk open-jtalk-mecab-naist-jdic hts-voice-nitech-jp-atr503-m001
```

| ファイル | 役割 |
|---|---|
| `kit.py` | スライド部品（見出し・箇条書き・表・フロー図・ダンプの絵など） |
| `deck_a.py` 〜 `deck_e.py` | 本文。1枚 ＝ `add(html, narration)` の1回 |
| `style.css` | スライドの見た目。動画用に文字を大きくしてあります |
| `build.py` | レンダリング・音声合成・結合 |
| `make.py` | 台本の書き出しと `build.main()` の呼び出し |

スライドを1枚足すときは `deck_*.py` に `add(page('見出し', 本文), 'ナレーション')` を足すだけです。
順番は `deck_a → deck_e` の読み込み順で決まります。

## 内容の裏付け

このスライドの法令引用は、元のPDFで検証した内容をそのまま使っています。
検証の記録は `../verify/` `../verify2/` `../verify3/` にあります。
条文や罰則を直すときは、必ずPDF側と両方を直してください。
