# NotebookLM に読ませる原稿

NotebookLM の**音声概要**で、二人のホストに解説してもらうための原稿です。

| ファイル | 中身 |
|---|---|
| [`読ませる原稿.pdf`](読ませる原稿.pdf) | **これをアップロードします。**全8ページ。PDFなら確実に読み込めます |
| [`読ませる原稿.md`](読ませる原稿.md) | 同じ中身の元原稿。**直すときはこちら。**全13章・約8,200文字 |
| [`カスタマイズ指示.md`](カスタマイズ指示.md) | 音声概要の「カスタマイズ」欄に貼る指示文。全体用・要点用・訂正の章だけ用の3種類 |

## 先に知っておいてください

**NotebookLM の音声概要は、渡した台本をそのまま読み上げる機能ではありません。**
資料を読んで、二人のホストが**自分たちの言葉で話し直します。**

ですから、ここに置いてあるのは**対話の台本ではなく、話の材料になる解説原稿**です。
対話の台本のほうは [`../radio/台本.md`](../radio/) にあります（こちらは合成音声で既に音になっています）。

**条文番号や数字が入れ替わることがあります。**要約して話し直す以上、避けられません。
**社内に配る前に、必ず一度通して聞き、原稿と突き合わせてください。**

## 使い方

1. NotebookLM で新しいノートブックを作る
2. `読ませる原稿.pdf` をアップロードする（`.md` でも読めますが、PDFのほうが確実です）
3. 音声概要を作る画面で**カスタマイズ**を開き、`カスタマイズ指示.md` のAをそのまま貼る
4. 生成する（数分かかります）
5. **通して聞いて、原稿と突き合わせる**

朝礼用に短いものが欲しいときはB、訂正の章だけ流したいときはCを使ってください。

## 社名について

**この原稿の会社名はすべて仮称です。**A運送・B砕石・C砂利店・D建設・E運転者で、実名は入っていません。

NotebookLM に入れるということは、資料を Google に渡すということです。
この資料は**取引先の実名と、その取引が適法か違法かの判定**を含むので、実名のまま出すと
こちらの照会が相手の調査の端緒になりかねません。照会書を仮称にしたのと同じ考え方です。

仮称と実名の対応は [`../21_運輸局への照会事例集.md`](../21_運輸局への照会事例集.md) の 0-3 にあります。
**その対応表はアップロードしないでください。**

実名入りの資料をどうしても読ませたい場合は、本編PDFをそのまま上げることもできますが、
**その判断は先にしておいてください。**一度上げたものは戻せません。

## 中身の出どころ

本編PDF『傭車の考え方と利用運送の登録判断』の**第65〜69章（白ダンプの早見表）**を軸に、
58〜63章（自家用ダンプの事務連絡）と70章（運輸局への照会）から抜いています。
[`../radio/`](../radio/) のラジオ番組と同じ範囲です。

第8章の訂正は [`../verify6/I_早見表の再検証.md`](../verify6/) の I-1 に対応します。

## 直すとき

本編PDFを直したら、この原稿も直してください。**自動では追随しません。**
原稿は本編から手で抜き出したもので、生成スクリプトはありません。

`.md` を直したら、PDFも作り直してください。

```bash
pip install markdown playwright
python3 src/gen_pdf.py
```

実名が混ざっていないかは、次で確かめられます。**両方とも 0 であること。**

```bash
grep -c "石名坂\|沢口\|熊谷" 読ませる原稿.md
python3 -c "import pypdfium2 as p; d=p.PdfDocument('読ませる原稿.pdf'); t=''.join(d[i].get_textpage().get_text_range() for i in range(len(d))); print(sum(t.count(w) for w in ['石名坂','沢口','熊谷']))"
```
