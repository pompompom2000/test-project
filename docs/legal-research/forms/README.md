## 使う前に差し替えるところ

`〇〇` となっている箇所をすべて自社の情報に置き換えてください。

**許可証提出依頼書**
- 文書番号、発信日、提出期限
- 住所・郵便番号、代表者名、担当者名、TEL / FAX / メールアドレス
- 宛先（「お取引先各位」を個別社名にする場合）

**副業兼業届出書**
- 冒頭の宛先（有限会社石名坂商事 か 株式会社石名坂 か）

**労働時間の上限設定書**
- 当事者欄はすべて記入式です。差し替える固定文言はありません

**白ダンプの早見表**
- 差し替えるところはありません。そのまま印刷して使えます
- **判定表のページだけA4横**になっています（列が7つあるため）。両面印刷する場合は用紙の向きにご注意ください
- 「現場の1枚」（積込み前チェック）は単独ページなので、そこだけ抜いて運転席・配車室に掲示できます

## 副業兼業届出書 ― なぜ要るのか

**労働基準法38条1項**は「労働時間は、**事業場を異にする場合においても**、労働時間に関する
規定の適用については**通算する**」と定めています。「事業場を異にする場合」とは
**事業主を異にする場合をも含みます**（昭和23年5月14日付け基発第769号）。

午前にA社で4時間、午後にB社で5時間なら通算9時間で、8時間を超える1時間は時間外労働です。

一方で、**令和2年9月1日付け基発0901第3号 第3の1(2)** は次のように述べています。

> 労働者からの申告等がなかった場合には**労働時間の通算は要せず**、また、労働者からの申告等により
> 把握した他の使用者の事業場における労働時間が事実と異なっていた場合でも**労働者からの申告等により
> 把握した労働時間によって通算していれば足りる**

つまり **申告させる仕組みを作ること自体が、そのまま防御になります。**
就業規則や労働契約に副業・兼業の届出制を定めたうえで、この様式を使ってください。

**「労働契約を締結した日」を必ず記入させてください。** 所定労働時間は
**労働契約の締結の先後の順**に通算するため（同通達 第3の2）、どちらが使用者A・使用者Bに
なるかがこの日付で決まります。

**「運転業務の有無」も聞いてください。** 土砂等の運搬に従事する場合、改善基準告示の
拘束時間・運転時間も通算して管理する必要があります。

## 労働時間の上限設定書（管理モデル）― なぜ要るのか

実労働時間を毎日突き合わせるのは現実的ではありません。
**同通達 第5**は、これを避けるための「管理モデル」を示しています。

> 副業・兼業の**開始前に**、……使用者Ａの事業場における法定外労働時間と……使用者Ｂの事業場における
> 労働時間（所定労働時間及び所定外労働時間）とを合計した時間数が**単月100時間未満、複数月平均80時間以内**と
> なる範囲内において、各々の使用者の事業場における労働時間の上限をそれぞれ設定し、各々の使用者が
> それぞれその範囲内で労働させる
>
> これにより、使用者Ａ及び使用者Ｂは、……**他の使用者の事業場における実労働時間の把握を要することなく
> 法を遵守することが可能となる**

**割増賃金の分担**（第5の2・第5の3(3)）
- 使用者A ― 自らの事業場における**法定外労働時間**の労働について
- 使用者B ― 自らの事業場における**労働時間**の労働について（所定労働時間を含む）
- 率は自らの事業場の就業規則等で定めた率（**2割5分以上**。通算して法定労働時間を超える部分が
  1か月60時間を超えた場合、その超えた時間のうち自ら労働させた時間については**5割以上**）

**導入の順序**（第5の3(1)）：一般に、使用者Aが労働者に管理モデルによることを求め、
労働者及び**労働者を通じて**使用者Bがこれに応じることで導入されます。
上限を変更するときも、**あらかじめ労働者を通じて**相手方に通知します（第5の4(2)）。

**通算されないもの**（第1の3）：休憩（34条）・休日（35条）・年次有給休暇（39条）。
36協定の限度時間（36条4項）・特別条項の年の上限（同5項）も事業場ごとです。

## 再生成

```bash
npm install docx
node src/許可証提出依頼書.gen.js
node src/副業兼業届出書.gen.js
node src/労働時間の上限設定書.gen.js
node src/白ダンプの早見表.gen.js
node src/運輸局照会書.gen.js
node src/照会記録票.gen.js
```

`node_modules/` はリポジトリに含めていません。

**注意**：この環境では LibreOffice（`soffice`）が動作しないため、生成した `.docx` の
**レイアウトを画面で確認できていません。**（既存の `許可証提出依頼書.docx` も同じ条件で作成しています。）
ZIPの健全性・必須パーツ・本文テキスト・表構造はスクリプトで検証済みです。
Word で開いたときに崩れがあれば、`src/` の該当箇所を直して再生成してください。
### 横向きページの落とし穴 ― 表が右にはみ出したら、まずここ

`docx` パッケージは、`orientation: PageOrientation.LANDSCAPE` を指定すると
**内部で width と height を入れ替えて**書き出します。
したがって `size` には **A4 縦の寸法（width: 11906, height: 16838）をそのまま渡します。**

入れ替え済みの値（`width: 16838, height: 11906`）を渡すと**二重に入れ替わり**、
`orient="landscape"` なのに**紙幅は A4 縦のまま（11906）**というページができます。
Word はこのとき幅210mmで組むので、横向き前提で作った表（14570）が
**右へ約87mmはみ出します。**2026年9月28日に `白ダンプの早見表.docx` で実際に起きました。

版面の幅は次のとおりです。**表の列幅の合計を、この値ぴったりに合わせてください。**

| 向き | 余白（左右） | 版面の幅 |
|---|---|---|
| A4 縦 | 25mm（1417 twips） | **9072 twips** |
| A4 横 | 20mm（1134 twips） | **14570 twips** |

あわせて、表には次の3つを入れてあります。

- `layout: TableLayoutType.FIXED` ― 既定の autofit だと Word が中身に合わせて列幅を
  作り直し、指定した幅を超えることがあります
- `tableHeader: true`（見出し行） ― 改ページ後も見出しが出ます
- `cantSplit: true`（ケース表の各行） ― 1ケースが改ページで上下に割れて、
  判定（○▲×）と根拠が別ページになるのを防ぎます

### 照会書を提出する前に

`運輸局照会書.docx` は**運輸局に渡す書面**なので、取引先の実名を書きません。
仮称と実名の対応表は [`../21_運輸局への照会事例集.md`](../21_運輸局への照会事例集.md) にのみ置いています。

照会書を直したら、**提出前に必ず**次を通してください。

```bash
python3 src/checkanon.py
```

実名（石名坂・沢口・熊谷）や「対応表」の語が残っていれば止まります。
あわせて、仮称（甲社・乙社・丙社・〔緑〕・〔白〕）が1つもない場合も警告します。
置き換えが途中で崩れていないかの裏取りです。

### 再生成したら必ず通す検査

`src/checklayout.py` を走らせて、**すべて「はみ出し 0」**になることを確認してください。

```bash
python3 src/checklayout.py
```

各セクションの版面の幅（用紙幅－左右余白）と、その中にある表の列幅の合計を突き合わせ、
はみ出している表があれば名前と数値を出します。行ごとのセル幅の合計も見ています。
